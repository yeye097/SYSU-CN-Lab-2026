# C 模块公布说明（供 A、B 参考）

> 角色 C 已完成：`origin_client.py`（源站通信）、`mock_origin_server.py`（可控测试源站）、`traffic_generator.py`（抓包流量工具）、`test_origin_client.py`（12 项测试全部通过）。以下为三方协作所需的全部约定，A 定阶段 0 方案时可直接参考本文与 C 的现有代码。

## 一、可控测试源站 `mock_origin_server.py`

- 启动：`python mock_origin_server.py --port 8000`（默认 `127.0.0.1:8000`，多线程并发，每连接独立线程）
- 端口约定：代理 `8888`，源站 `8000`，单元测试源站 `18000/18001`

| 路径 | 行为与首部 | 用途 |
| :--- | :--- | :--- |
| `/` 或 `/index.html` | 200 OK，Content-Length 定界；带 `Last-Modified`、`ETag`、`Date`、`Cache-Control: public, max-age=10`；条件命中返回 304（无正文） | 场景 1/2/3/4/5 主测试页 |
| `/chunked` | 200 OK，`Transfer-Encoding: chunked` | C 分块定界解码 |
| `/eof` | 200 OK，无 Content-Length，连接关闭定界 | C EOF 定界 |
| `/update` | 修改资源内容与时间戳（版本 v+1），返回新 ETag/Last-Modified | 场景 4 触发源站更新 |
| `/reset` | 资源重置为初始版本 v1 | 场景间状态复位 |
| `/status` | 返回当前版本/Last-Modified/ETag | 调试与报告取证 |
| `/delay?sec=N` | 延迟 N 秒后响应 | C 超时处理测试 |

## 二、`OriginClient`（`origin_client.py`）

- 构造：`OriginClient(default_timeout=5.0)`，B 通过构造参数注入（便于单测替换模拟对象）
- 调用：`fetch(request: HTTPRequest, conditional_headers=None) -> HTTPResponse`
- 条件首部传 `[("If-None-Match", etag)]` 或 `[("If-Modified-Since", ts)]`；传入时会覆盖请求中的同名首部（不重复）
- 行为要点：自动补全 `Host`；强制 `Connection: close`；304/204/HEAD 返回空正文；chunked 解码后去除 `Transfer-Encoding` 并补真实 `Content-Length`；三种定界（Content-Length / chunked / EOF）均已实现并经 12 项测试覆盖
- 抛出的异常（建议由 A 统一映射为客户端错误响应）：

| 异常 | 触发条件 | 建议映射 |
| :--- | :--- | :--- |
| `OriginTimeoutError` | 连接或读取超时 | 504 Gateway Timeout |
| `OriginConnectionError` | 拒绝连接/无法连通 | 502 Bad Gateway |
| `OriginProtocolError` | 响应不符合 HTTP 规范 | 502 Bad Gateway |

## 三、给 A 的注意点

1. **错误响应建议由 A 合成**：C 的 `fetch` 只抛异常不返回错误响应；当前代码中的 `safe_fetch`（合成 502/504）仅用于单测，请勿接入主链路，避免与 A 的错误映射重复；
2. **输出前重写首部**：`HTTPResponse.to_http_bytes()` 仅供调试，向客户端输出前须重新生成正确的 `Content-Length` 与 `Connection` 头，不得透传源站首部；
3. 源站已支持多线程并发，场景 5 代理→源站可并行建立多条 TCP 连接，抓包可见并发流。

## 四、给 B 的注意点

1. **锁外调用**：调用 `OriginClient.fetch` 必须在缓存锁之外（架构文档：不持有全局缓存锁进行网络访问）；
2. **条件验证优先级**：ETag（`If-None-Match`）优先，其次 Last-Modified（`If-Modified-Since`）；无验证标识则重新获取；
3. **304 处理**：收到 304 时复用本地缓存正文、刷新新鲜度并更新元数据；源站 304 响应无正文；
4. 源站 `/index.html` 的 `Cache-Control: public, max-age=10` 可直接用于测 HIT；`/update` 修改内容与时间戳后可测 304→200 转变。
